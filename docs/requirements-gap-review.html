01The honest starting point

The system built in early September works end to end, but it was built for an earlier brief: Kayak data, 30-day rentals, three vehicle types and a fixed list of ten airports. The client's confirmed scope changes the data source, rental length, search area and users.

Four facts that matter most

  • No Skyscanner search has ever run. All 1,047 offers in the database came from Kayak, all for 30-day rentals. The Skyscanner connection exists in code but is untested.
  • Skyscanner 330-day results are unproven. The Skyscanner scraper accepts any return date, so a 330-day search can be requested. Whether Skyscanner returns offers for it is unknown. The Budget screenshot proves Budget's own website quotes 330 days — not Skyscanner.
  • Some required fields may not exist in Skyscanner's data. The scraper's documented output has vehicle, supplier, price, seats, bags, fuel policy, vehicle code, pickup type and booking link. It does not list the booking provider, the depot address or a tax breakdown. These may be inside the full raw response the scraper also saves; that must be checked.
  • Skyscanner is only reachable by scraping. The official Skyscanner API is not available for this kind of tool. The scraper used is a small third-party service (6 users, 158 runs as of today).

05Questions for the client

The confirmed scope answered most earlier questions. These remain. The first four should be answered before development starts; the rest have a suggested default and can be confirmed later.

Answer before development

Q1 · Data access and terms

Do you accept using a third-party Skyscanner scraper?

Skyscanner's official API is only for large travel websites and does not allow automated searching. The only practical way to get Skyscanner data is a third-party scraping service, which is against Skyscanner's terms of use. Because your business charges customers a fee, this carries more risk than personal use, and the service could stop working without notice.

Suggested — Confirm in writing that you accept this, and consider brief legal advice.

Q2 · Verification budget

May we spend about $10–20 to test real 330-day Skyscanner searches first?

This checks, before building, whether Skyscanner returns 330-day offers, whether the booking provider, depot address, taxes and mileage are included, and what one search really costs.

Suggested — Yes; 3–5 days, results shared before development continues.

Q3 · If 330-day offers are limited

What should happen if Skyscanner returns few or no 330-day offers?

The Budget screenshot shows Budget's own site can quote 330 days, but Skyscanner may not show those offers, or only from a few companies.

Options: (a) show only what Skyscanner returns, even if little; (b) also allow rental-company websites such as Budget and Avis for long rentals; (c) stop and reconsider.

Suggested — Decide after the Q2 test results.

Q4 · Monthly search budget

What is the maximum monthly spend on searches?

Cost depends on how many locations fall inside the chosen distance and how many searches are running daily. A larger radius costs much more: doubling the distance roughly quadruples the area. The system can stop daily searches when a monthly limit is reached.

Suggested — Set a starting limit, for example $200–$300 per month, and adjust after measuring real costs.

Can be confirmed later (suggested default given)

Q5 · Missing fields

If Skyscanner does not provide booking provider, depot address or tax breakdown, is that acceptable?

These fields are not in the scraper's documented output. If missing, we show "not provided by Skyscanner" instead of guessing.

Suggested — Acceptable; show what is available and mark the rest clearly.

Q6 · Distance

Is straight-line distance from the ZIP code acceptable?

Driving distance needs a paid routing service. If a depot's exact address is not available, distance would be measured to the searched city or airport and marked approximate.

Suggested — Straight-line distance, marked approximate when needed.

Q7 · Maximum radius

What is the default distance, and the largest distance allowed?

Suggested — Default 50 miles; show cost and ask for confirmation above 150 miles.

Q8 · Results per location

Should each location return all offers, or only the cheapest ones?

The scraper returns Skyscanner results cheapest first and lets us cap how many it returns; cost rises with the number of offers. Returning only the cheapest 100–150 per location greatly reduces cost and still finds the lowest prices, but may miss rarer vehicles such as 15-seat vans.

Suggested — Cheapest 150 per location by default, with an option to run a complete search.

Q9 · Pickup time and driver age

What pickup/return time and driver age should searches use?

Both affect price and availability. Drivers under 25 or over 70 may pay extra at the counter.

Suggested — Pickup and return 10:00; driver age 30; editable per search.

Q10 · How long a search keeps running

How long should a saved search run daily, and how many can run at once?

Suggested — Runs daily until staff pause it or the pickup date passes; up to 10 active searches at once.

Q11 · Customer details

What customer information should be stored with each search?

Storing personal details adds privacy responsibilities.

Suggested — A customer reference or first name only, plus internal notes.

Q12 · Notifications

How should staff learn about daily changes?

Suggested — Shown on the dashboard; optional daily email summary.

Q13 · Login details

Who are the two users, and is two-step login wanted?

Suggested — Two email accounts with passwords, plus two-step login with an authenticator app.

Q14 · Hosting

Where should the system run?

A small cloud server lets both users access it from anywhere; an office computer is cheaper but must stay on for daily searches.

Suggested — Small cloud server, about $15–$50 per month excluding search costs.

Q15 · Conditions to show

Which rental conditions matter most?

Suggested — Mileage, fuel policy, cancellation, deposit, pickup type (airport / shuttle / city), age rules.

Q16 · Price history retention

How long should results and history be kept?

Suggested — 12 months.
