01Summary

The tool is an internal search system for a deal-finding business. Two staff users enter a customer's requirements — a ZIP code, a distance, optionally states, and a pickup date. The system searches Skyscanner for complete 330-day rentals at every location in range, ranks every vehicle by average cost per 30 days, and re-runs the search daily so staff can see new deals, price moves and deals that disappear.

The confirmed scope resolves most of the open questions from earlier rounds. Three things now decide whether the plan holds:

Three facts to accept before development starts

  • There is no official Skyscanner access for this use. The Skyscanner partner API is only granted to high-traffic travel businesses and forbids automated searching. Skyscanner data is therefore only reachable through a third-party scraping service, which breaches Skyscanner's terms. Because the business charges customers a fee, that exposure is higher than it would be for personal use.
  • 330-day search through Skyscanner is not yet proven. The Budget screenshot proves Budget's own website quotes 330 days. It does not prove Skyscanner returns 330-day offers, nor how many suppliers do.
  • Skyscanner does not search by ZIP code and radius. It searches by airport or city. Covering "every location within 50 miles" means the system must work out which searches to run, and cost scales with how many that is.

All three can be settled with about one week of verification work and roughly $10–20 of test searches, before committing to the full build. That verification is Phase 0 in section 14.

04What must be proven first

Each gate is a yes/no question that can be answered with a small number of real searches. If any gate fails, the plan changes before significant money is spent. These are ordered by how much depends on them.

Gate 1 · data access

Can Skyscanner car-rental data be obtained reliably?

The official Skyscanner Car Hire API is not available: access requires an established travel business with more than 100,000 monthly visitors, Live Pricing may only be called when a real user searches, and default limits are 15 searches per minute. None of that fits an automated internal tool.

The practical route is a third-party Apify scraper. The candidate, scrapeunblocker/skyscanner-car-hire-scraper, is already integrated as an adapter in the prototype but has never been run. It had 5 users and about 105 runs when reviewed, so reliability is unproven.

TestRun 10 searches across different US locations on different days. Pass if at least 9 succeed and return offers.

Gate 2 · the 330-day rental

Does Skyscanner return complete 330-day quotes?

Budget's own site quotes 28 to 330 days, and Avis's long-term programme runs 15 to 330 days. Whether those long rentals appear through Skyscanner — and from how many suppliers — is unknown. A 30-day pickup window plus 330 days reaches about 360 days ahead, inside Skyscanner's one-year search range, so dates are not the obstacle; supplier participation is.

TestSearch the same airport for 330 days and for 30 days. Pass if the 330-day search returns offers from at least two major suppliers with a real total price, not an error or a daily rate multiplied out.

Gate 3 · locations and distance

Can every location in range be found, and its distance measured?

Skyscanner searches by airport or city name, not by ZIP and radius. A search for a city returns depots across that area, but the scraper's documented output (vehicle, supplier, price, seats, bags, fuel policy, ACRISS code, pickup type, booking link) does not include depot addresses or coordinates. Without them, the distance from the customer's ZIP can only be approximated. The scraper also saves Skyscanner's full raw response, which may contain depot details.

TestInspect the raw response for one city search. Pass if depot names and either coordinates or full street addresses are present for most offers.

Gate 4 · complete price

Does the quoted total include taxes and mandatory fees?

Comparison sites usually show a total including mandatory charges, but some fees — airport concession fees, young-driver fees, deposits — are often payable at the counter and shown separately or not at all.

TestCompare 5 Skyscanner totals against the same booking on the supplier's own checkout page. Pass if they match within a few percent, or the difference is identified in the listing.

Gate 5 · cost per search

What does one complete search really cost?

The scraper charges about $1.50 per 1,000 offers returned. Searching every vehicle category for a whole metro area could return hundreds of offers per location searched. The true cost depends on offer counts that have not yet been measured for 330-day searches.

TestRecord offers returned and charge for each Gate 1–3 search. Produce a measured cost per location and per typical saved search.

Gate 6 · supplier coverage

How much of Skyscanner's inventory does a server-side search see?

Skyscanner's own documentation states roughly half of car-hire quotes come from suppliers that need the end user's IP address. A server searching on someone's behalf may see fewer suppliers than a person searching in a browser. If the cheapest deals come from those suppliers, the tool will miss them.

TestRun the same search in a normal browser on skyscanner.com and through the scraper. Pass if the scraper finds at least 80% of the suppliers and the cheapest browser deal.

If a gate fails

  • Gate 1 fails: test a second Skyscanner scraper (for example canadesk/skyscanner-cars, around 26 users and 83,000 runs), or build a dedicated scraper, which costs more to maintain.
  • Gate 2 fails: Skyscanner cannot deliver the core requirement. The client would need to allow another source for long rentals, such as supplier sites directly.
  • Gate 3 fails: show distance to the searched airport or city centre instead of each depot, clearly labelled as approximate.
  • Gate 5 shows high cost: cap offers per location to the cheapest results, and reduce how often saved searches run.

05How a search works

The workflow follows the client's own five steps: a customer asks, staff search, the system finds deals, staff review, and a deal is presented.

A worked example

A customer asks for the cheapest 330-day rental within 40 miles of downtown Denver, picking up 1 October.

  1. Staff enter ZIP 80202, distance 40 miles, state CO, pickup 1 Oct 2026, 10:00. The system fills in return 27 Aug 2027, 10:00.
  2. The system finds the search locations inside 40 miles: Denver International Airport, Denver, Aurora, Lakewood, Littleton, Westminster and Boulder — seven searches.
  3. Each runs as one 330-day Skyscanner search covering every vehicle category.
  4. Offers are merged. A Budget branch appearing in both the Denver and Aurora results is kept once.
  5. Each offer gets its distance from 80202, its category, and its 30-day average. A $12,650 total becomes $1,150 per 30 days.
  6. Results are stored and listed cheapest first, with those at or under $1,100 highlighted.
  7. Staff filter to minivans, compare the top three, check their mileage and conditions, and present one to the customer.
  8. The search stays active. Tomorrow at 06:00 it runs again and marks anything new, cheaper, dearer or gone.

Location list and prices in this example are illustrative, not measured.

06Finding every location in range

This is the most technically involved part of the requirement, because Skyscanner has no "within X miles of this ZIP" search and publishes no list of its depots.

The approach

  1. Convert the ZIP to a point. Use the US Census ZIP Code Tabulation Area file, which is free and gives a centre point for every ZIP. No paid geocoding service needed.
  2. Hold a table of search anchors. Every US commercial airport (public-domain airport data) plus every US city above a population threshold (Census place data), each with coordinates and state. Built once, stored locally.
  3. Pick anchors in range. Select every anchor whose distance from the ZIP is within the radius, filtered to the chosen states.
  4. Search each anchor on Skyscanner. A city search returns depots across that city — neighbourhood and smaller branches included — not just a downtown office.
  5. Record every depot seen. Each depot found is saved with its name and address. Over time the system builds its own list of real Skyscanner depots, which makes later searches more precise.
  6. Measure and trim. Calculate each depot's distance from the ZIP and drop any that fall outside the radius, since a city search can return depots beyond it.

Why radius drives cost

Area grows with the square of the radius. Doubling the distance from 25 to 50 miles roughly quadruples the area, and typically the number of anchors that need searching. Staff should see the number of searches and the estimated cost before running a new request. Large radii — 150 miles or more — should require confirmation.

Distance accuracy

If Gate 3 confirms depot coordinates or addresses are available, distance is measured to each depot, straight line. If they are not, distance falls back to the searched city or airport and is labelled approximate. Straight-line distance is used rather than driving distance, which would need a paid routing service and adds little for ranking purposes.

07Pricing, vehicles and results

Price calculation

Return date      = pickup date + 330 days      (same time of day)
Total price      = Skyscanner quoted total     (stored exactly, never recalculated)
Average per 30 days = Total price ÷ 11
Target           = $1,100 per 30 days          (highlight only, never hides results)

Prices are stored as exact decimals in the currency quoted, US dollars for the US market. Where a listing separates taxes and mandatory fees, both the base and the fees are stored and shown. Where it does not, the total is shown with a note that the breakdown was not provided.

Vehicle types

Every category is searched and stored. Each offer is classified using its ACRISS code — the industry four-letter code where the second letter identifies body type — backed by seat count and model name when the code is missing. Three quick filters sit above the results:

Quick filterRuleExample
MinivanVan body type with 7–8 seats, or a known minivan modelChrysler Pacifica, Toyota Sienna
Large SUVSUV body type in full-size, premium or luxury category, or a known 3-row modelChevrolet Tahoe, Ford Expedition
True passenger vanVan body type with 10 or more seats, or a known passenger-van modelFord Transit 12 or 15 seat, Chevrolet Express

Seat counts need checking

In earlier testing, a listing described a Honda Odyssey as a "passenger van". It seats eight. Listings can mislabel vehicles, so the passenger-van filter uses seat count as well as the label, and staff should confirm capacity with the supplier before presenting a 12-passenger vehicle to a customer.

Results list

  • Default sort: lowest average per 30 days first.
  • Other sorts: lowest total, nearest, most seats.
  • Filters: vehicle quick filters and all categories, rental company, booking provider, maximum distance, maximum monthly price, state, unlimited mileage only, change status (new, cheaper, dearer).
  • Offers at or below the target carry a clear highlight; all others remain visible.
  • Duplicate offers of the same car from the same depot are merged, keeping the cheapest booking provider and listing the others.

08Daily tracking

Every saved search is either active or paused. Active searches re-run once a day. Each run is stored separately, so price history builds up over time.

How changes are detected

Each deal has a stable identity built from depot, rental company, vehicle code or model, pickup date and rental length. The booking provider is deliberately excluded, so the same car sold through two sites is one deal. Comparing today's run against yesterday's gives four outcomes:

StatusMeaning
NewNot seen in any earlier run of this search
CheaperTotal fell by at least 3% or $20, whichever is larger
DearerTotal rose by at least 3% or $20, whichever is larger
GoneSeen yesterday, missing today — shown once, then kept only in history

The 3% or $20 threshold keeps ordinary daily movement from filling the list. On a $13,000 total, a change must be at least $390 to be flagged.

Search lifecycle

  • A search runs daily until staff pause it, or until its pickup date arrives, when it stops automatically.
  • History is kept after a search ends, so past searches can be reviewed.
  • Staff can run a search immediately at any time, outside the daily schedule.
  • If a run fails, it retries automatically; persistent failures appear on the search page rather than failing silently.
  • A run that returns far fewer offers than usual is flagged as a possible data problem, because an empty result with no error is the most dangerous failure for a price tool.

09Users, login and security

The tool handles customer requests and deal data, so a simple login is needed — but nothing more.

Accounts
Two named accounts, created by the developer. No sign-up page, no public pages, no customer accounts.
Sign-in
Email and password. Passwords stored using a modern slow hash (Argon2). Session held in a secure, HTTP-only cookie.
Protection
Login attempts rate-limited and temporarily locked after repeated failures. All traffic over HTTPS. Password reset handled by the developer rather than a public reset flow.
Optional
Two-factor sign-in with an authenticator app. Recommended given the business handles customer requests; small addition.
Audit
Each saved search records which user created it, and each run records when it happened and what it cost.
Secrets
The data-provider token and database password live in server configuration only, never in the browser.

Because only two people use the system, the infrastructure is deliberately small: no load balancing, no caching layer, no autoscaling. A single small server comfortably handles two users and a few dozen daily searches.

12Costs

There are two kinds of running cost: the data provider, which is charged per search result and dominates, and hosting, which is small and fixed.

Data cost per search

The Skyscanner scraper charges about $1.50 per 1,000 offers returned. The number of offers returned by a 330-day, all-category search at one location is not yet measured — that is Gate 5. For comparison only, a 30-day van-and-SUV search at Atlanta on a different site returned 425 offers. All categories will return more.

The cheapest-results cap fits the goal

The priority is the lowest price, and Skyscanner results arrive cheapest first. Limiting each location to its cheapest offers cuts cost substantially without losing the deals that matter. The trade-off: a pricier vehicle type, such as a 15-seat van, may fall outside the cap. The system will offer two modes per search — cheapest, capped, and complete, uncapped — and show the cost of each before running.

Controls built in

  • Estimated cost shown before any new search runs.
  • Each individual Skyscanner request hard-capped, so one faulty search cannot run away.
  • A monthly spending limit; daily runs pause and staff are alerted when it is reached.
  • Searches stop automatically once their pickup date passes.
  • Run log showing spend per search and per month.

The future multi-date feature

Trying every pickup date in the next 30 days multiplies every figure above by up to 30. A capped metro search that costs $1.15–$2.25 per run would cost $35–$68 per run across 30 dates. That is why it is correctly deferred: the v1 cost measurements decide whether it is affordable, and a sampled version — for example every seventh day — may be a sensible middle ground.

16Remaining decisions

The confirmed scope answers most questions. These remain, and none blocks Phase 0.

  1. Accept the data-access risk in writing. Skyscanner data is only available through a third-party scraper that breaches Skyscanner's terms, for a fee-charging business. Legal advice recommended.
  2. Approve Phase 0 and its $10–$20 of test searches.
  3. Monthly data budget. A figure lets the system enforce a spending limit, for example $300 or $600 per month.
  4. Default and maximum radius. Suggested default 50 miles, confirmation required above 150.
  5. Default pickup time and driver age. Suggested 10:00 and age 30. Drivers under 25 or over 70 may face counter surcharges not in the quote.
  6. Hosting. A small cloud server so both users can access it from anywhere, or a computer in the office.
  7. Two-factor sign-in. Recommended; confirm whether wanted.
  8. Which conditions matter most on the results screen: fuel policy, cancellation, deposit, pickup type, age rules.

17Acceptance criteria

Version 1 is complete when all of the following are true.

  1. Only the two authorised users can sign in; no page is reachable without signing in.
  2. Staff can create a search from a ZIP, distance, optional states and one pickup date, and the return date is calculated as pickup + 330 days.
  3. Every search requests the full 330-day rental from Skyscanner, never shorter rentals.
  4. Results include every vehicle category, with minivan, large SUV and passenger-van filters working.
  5. Every result shows all fields in section 2 that Skyscanner provides, and clearly marks any it does not.
  6. Average per 30 days equals total ÷ 11, and results sort lowest average first by default.
  7. Results above $1,100 are shown; results at or below are highlighted.
  8. Only depots within the chosen distance appear, with distance shown.
  9. Estimated cost appears before a new search runs, and a monthly spending limit is enforced.
  10. Active searches run daily, store every run, and correctly mark new, cheaper, dearer and gone deals.
  11. Price history is visible for each deal.
  12. Failed or suspiciously empty runs are reported on screen, never silently.
  13. Searches stop automatically after their pickup date.
